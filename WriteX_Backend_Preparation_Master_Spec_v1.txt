WRITEX BACKEND PREPARATION MASTER SPEC v1
=========================================

Purpose
-------
Prepare the WriteX website backend in a controlled, production-ready way.

Current state:
The website is currently a brochure / SEO / WhatsApp lead-capture frontend.

Immediate backend objective:
Build a real lead backend before building the full LTS/PMT client portal.

Backend phases:
1. Phase 1: Quote Lead Backend
2. Phase 2: File Upload + Email Notification
3. Phase 3: Admin Lead Panel
4. Phase 4: LTS/PMT Client Portal Integration

Do NOT build the full client portal until LTS/PMT API details are available.

Approved Stack
--------------
Frontend + Backend:
- Next.js full-stack app

Hosting:
- GoDaddy VPS
- Do not rely on basic/shared GoDaddy Node.js hosting for portal/backend

Database:
- AWS RDS PostgreSQL

File Storage:
- AWS S3 private bucket

Email:
- Resend initially
- AWS SES-compatible later

Auth:
- Custom admin login
- SQL admin_users table
- Secure HTTP-only cookie/session
- No JWT/localStorage for admin session

Domain/DNS:
- GoDaddy

Future integrations:
- LTS API
- PMT API

Core Principles
---------------
1. LTS will be source of truth for work/order journey.
2. PMT will be source of truth for payment status.
3. Website backend should never connect directly to LTS/PMT databases.
4. Frontend should never receive database secrets, S3 secrets, or service-role keys.
5. S3 files must be private.
6. File access should happen using temporary signed URLs.
7. Download unlock should later depend only on PMT settled/approved status.
8. If a backend function is not connected, public UI must not fake it.

Phase 1: Quote Lead Backend
---------------------------
Goal:
When a visitor submits quote form, the lead should be saved and WriteX team should be notified.

Required API:
POST /api/quote

Required fields:
- name
- email
- whatsapp
- country
- service_required
- academic_level
- subject
- word_count
- deadline
- instructions
- lead_source
- page_url
- utm_source
- utm_medium
- utm_campaign

Validation:
- name required
- whatsapp required
- service_required required
- deadline optional but preferred
- email optional but validated if provided
- instructions optional
- reject obvious spam

Response:
Success:
{
  "ok": true,
  "leadId": "...",
  "message": "Thanks. WriteX will review your brief and respond with a quote."
}

Failure:
{
  "ok": false,
  "message": "Something went wrong. Please send your brief on WhatsApp."
}

Fallback:
If database/email is not configured, frontend should open WhatsApp with prefilled lead details.
Do not pretend the lead has been saved.

Phase 2: File Upload + Email Notification
-----------------------------------------
Goal:
Allow quote form users to upload brief/rubric/draft securely.

Required API:
POST /api/upload-brief

Storage:
- AWS S3 private bucket
- Do not make files public
- Store file metadata in database
- Generate private object key

Allowed file types:
- PDF
- DOC
- DOCX
- PPT
- PPTX
- XLS
- XLSX
- CSV
- JPG
- JPEG
- PNG
- TXT
- ZIP if needed

File size:
- Suggested max 25 MB initially

Database:
file_assets table

Required email notifications:
- New quote lead email to WriteX sales/support
- Uploaded file included as secure internal reference, not public link
- If using temporary signed links, keep expiry short

Phase 3: Admin Lead Panel
-------------------------
Goal:
Internal team can see quote leads and update lead status.

Admin pages:
- /admin/login
- /admin/dashboard
- /admin/leads
- /admin/leads/:id

Admin roles:
- super_admin
- sales
- support
- accounts
- viewer

Admin login:
- email + password
- password hashed using bcrypt or Argon2
- session via secure HTTP-only cookie
- no passwords in plain text
- no JWT in localStorage

Lead statuses:
- new
- contacted
- quoted
- converted
- lost
- spam

Admin actions:
- view lead
- update status
- add internal note
- copy WhatsApp message
- open WhatsApp
- view uploaded file metadata
- create signed file link if authorized

Phase 4: LTS/PMT Client Portal Integration
------------------------------------------
Do this later after API details are available.

Future client portal:
- /client-login
- /client/dashboard

Client login:
- Invoice ID
- Registered WhatsApp number
- OTP verification

Data sources:
- LTS: journey/order progress/files
- PMT: invoice/payment status/payment instructions

Client dashboard:
- Greeting with client name
- Invoice summary
- Work journey
- Preview locked/unlocked

Preview/download:

Security Requirements
---------------------
- Use secure HTTP-only cookies
- No auth/session token in localStorage
- Hash passwords using bcrypt or Argon2
- Hash OTPs, do not store plain OTP
- Rate limit login and OTP attempts
- Validate inputs with Zod or equivalent
- Log preview/download/payment events
- Signed URLs must expire
- No public S3 objects
- No secrets exposed to frontend
- Server-side payment verification only
- Public UI must not show mock backend/TODO text
